# Agent-model interface (Gap 19/20/21) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every event where the harness does not know what the agent did visible,
attributable and excluded from the published numbers, and make every experimental
condition that determines those numbers appear in the report.

**Architecture:** Three layers, in dependency order. (1) The *schema* learns to carry the
new evidence across the container boundary: `ToolCall` gains `arguments_parse_failed` /
`raw_arguments`, `Transcript` gains `model_retry_count`, all with retro-compatible
defaults. (2) The *producers* populate it: `agent_loop.py` refuses to execute a tool whose
arguments are not a readable JSON object, `model_client.py` gets an explicit `max_tokens`,
an explicit per-request timeout, a bounded per-case retry budget for transient failures,
and reads the real cost from the OpenRouter response instead of a local price table. (3)
The *consumers* act on it: one pure classifier (`metrics.transcript_unusable_cause`) is
the single definition of "this transcript cannot be judged", used by `sequence.py` (keeps
the case out of `metric_cases`), by `compute_metrics` (second barrier + per-cause
counting), by `run_batch.py` (publication threshold) and by `report.py` (declares the
exclusions with their causes and shows at least one in full). `criteria.py` gets an
independent second barrier. A new `provenance.py` captures the experimental conditions at
run start and a new `inspect_run.py` is the reproducible check any third party can run on
a run directory.

**Tech Stack:** Python 3.11+, pytest, the `openai` SDK (already a dependency — its
exception hierarchy is the transient/permanent taxonomy), `httpx` (already a dependency —
preflight), no new dependencies.

**Spec:** `docs/design/2026-08-21-interfaccia-modello-agente-design.md` (committed
`bbb03c1` + `296bf3e`; went through a 4-agent council checkpoint and a `grill-with-docs`
pass — implement what it specifies, do not re-derive it, do not reopen it). Its section 7
("Mapping Requisito -> Verifica", R1-R20) is the acceptance criteria for this plan: every
row maps to a named test below.

## Parameter decisions (design doc section 11, fixed here)

The design doc leaves six parameters to this plan and states that none of them changes the
architecture. They are fixed as follows; each is declared in the report by Task 10.

| # | Parameter | Value | Why this value |
|---|---|---|---|
| 11.1 | Retry policy | **2 retries per case, shared across the whole loop**, backoff `1.0s` then `3.0s`, only on `openai.APIConnectionError` / `APITimeoutError` / `RateLimitError` | The budget lives on the *client instance*, and `run_case.py:66` builds exactly one client per case — so "per instance" *is* "per case", with no new plumbing. The retries add at most `2 x (20s timeout + backoff) ~= 44s` to a case, whatever `max_turns` does, instead of `8 x retry-chain`, which is what a per-call budget would allow. That bounds the *increment*, NOT the total: see "Blast radius" below, which states the combined worst case and why it is not under `AGENT_TIMEOUT_S`. |
| 11.2 | `max_tokens` | **2048** | The agent's replies are short support answers plus tool calls; 2048 tokens (~8KB) is far above anything observed in the 31-case run, and it also bounds `raw_arguments`, which is otherwise unbounded model-written text that reaches the vendor verbatim. |
| 11.3 | Run-invalidity threshold | **`transcript_unusable > max(1, 10% of metric-eligible cases)` => `report.md` is not written, exit code 1** | On 31 cases this refuses to publish from 4 exclusions up. A fraction, not a count, because Plan 6 will grow the dataset — with an absolute floor of 1, because a bare fraction is zero-tolerance below 10 cases (1/9 = 11% > 10%) and would block the small hand-written sequences `counts_toward_metric` exists to support (Gap 15 mode 2). A single excluded case never blocks publication: the report shows it in full with its cause, so the reader can judge it. Mirrors the discipline of the existing anti-shortcut gate (`run_batch.py:176-190`): refuse to write, never publish with a footnote. |
| 11.4 | Cap on the raw string echoed back to the model | **200 characters + `"..."`** | The same cap `report.py:38` already uses for transcript excerpts (`max_content_len=200`) — one convention in the repo, not two. |
| 11.5 | Unit of the `cost` field | **Verified live in Task 18, table removed in Task 19** | The design keeps `_PRICING_PER_MILLION_TOKENS` alive *as the oracle* for exactly this comparison. Task 18 is the only task in this plan that makes a network call; Task 19 is gated on its result, not on anything else. |
| 11.6 | Rationale for the `gpt-4o-mini` default | **Stays open, registered as an open limit** (Task 17) | The design (section 10) explicitly does not answer it; it is a separate experimental decision. |

### Blast radius of the retry policy (design section 5.3, the sizing constraint)

The budget is not "a retry chain under 120s". It is: up to `max_turns = 8` model calls per
case (`agent_loop.py:111,123`), all inside one `docker compose exec` bounded by
`AGENT_TIMEOUT_S = 120.0` (`run_batch.py:18`). Exceeding it yields `error_kind="infra"`
(`orchestrator.py:81`), and **three consecutive infra results truncate the whole batch**
(`sequence.py:262-271`). Hence:

- The retry budget is **per case, not per call**: at most 2 retries for the *entire* case.
- Each HTTP request gets an explicit **20s** timeout (today there is none at all, which is
  strictly worse: one hung request can eat the whole 120s window by itself).
- Worst added latency: `2 x (20 + backoff) = 44s`.
- **The combined worst case is ~204s, which is NOT under `AGENT_TIMEOUT_S`, and this plan
  does not make it so.** Both retries can be spent on a single turn (3 attempts x 20s + 1s
  + 3s = 64s on turn 1 alone), leaving up to 7 further turns at 20s each: ~204s. Even with
  zero retries, 8 x 20s = 160s already exceeds 120s. State this as one number, not split
  across two sections — a reader of this table alone must not come away believing the
  sizing was checked and found safe.
- What the sizing DOES buy, and it is not nothing: before this plan there was no
  per-request timeout at all, so a single hung request was unbounded; and a per-call retry
  budget would have made the pathological case `8 x 64s`. A typical observed case is well
  under 30s.
- `AGENT_TIMEOUT_S` is deliberately **not** raised: it is a published experimental
  condition, and changing it without evidence would swap one undeclared change for
  another. Registered as an open limit in Task 17.

## Decisions derived from the design (declare, do not re-litigate)

These three are *not* in the design doc's text but follow necessarily from its
requirements. They are listed here so a reviewer can contest them explicitly instead of
finding them buried in a diff.

- **D-G — `Transcript.model_retry_count: int = 0`.** R12 requires every retry to be counted
  *even when it succeeds*, and the report is written on the host. A counter living inside
  `agent_loop`/`model_client` dies with the container process — the same argument the
  design makes in D4 for `ToolCall`. The only thing crossing the boundary is
  `transcript_to_dict()`'s output, so the count must be a `Transcript` field, with a
  default, exactly like the two `ToolCall` fields.
- **D-H — provenance is captured at run start and persisted to `run_output/provenance.json`.**
  Section 6.4 requires `_setup_notes()` to declare the measurer commit, the vendor commit
  and the resolved models. For a live run those are readable at report time because run and
  report happen inside the same `main()`. For `regenerate_report.py` — which is how a past
  run's report is rebuilt, and the tool section 4 relies on — reading them at report time
  would stamp *today's* commit onto *yesterday's* numbers: the exact defect this plan
  closes, committed by the tool meant to close it. So they are captured once, at run start,
  and written next to the raw data. A run directory without the file is declared "not
  recorded", never guessed.
- **D-J — the report reads the exclusions from `BatchResult`, not from `MetricsResult`.**
  `run_batch.py:192` and `regenerate_report.py:144` call
  `compute_metrics(result.metric_cases, ...)` — the list Task 6 has already purged. So
  `MetricsResult.transcript_unusable_count` is *structurally always zero* in the live
  pipeline, and a report built on it would print "0 excluded" on a run that excluded three
  cases. `render_report` therefore takes the authoritative dict from `BatchResult`, and the
  counter inside `MetricsResult` is repurposed: it is an **alarm**, not a display value —
  a nonzero value means an unusable case reached `compute_metrics`, i.e. the primary
  exclusion leaked, and the report says so in those words.
- **D-I — one classifier, four consumers; `error_count` shrinks.**
  `metrics.transcript_unusable_cause(case)` is the single definition of the bucket. It runs
  *before* the `v.status == "error"` check in `compute_metrics`, so a case that failed
  before the detector ever saw it (`orchestrator.py:79/81` -> `transcript is None` **and**
  an error verdict) is counted **once**, as `transcript_unusable`, not as a detector error.
  This is a deliberate change of meaning: `error_count` is documented as "verdicts in error
  *of the detector*" (design section 5.4 table), and an infra failure of ours never was
  that. The report must say so (Task 11), and the existing tests that assume the old
  behaviour must be updated, not deleted (Tasks 5, 6).

```python
@dataclass
class ToolCall:
    tool_name: str
    arguments: dict
    result: Optional[str]
    status: Status
    # Gap 19: the model emitted a tool-call arguments string that is not a
    # readable JSON object. Recorded explicitly instead of being absorbed into
    # arguments={} — bulk_export(state, **{}) succeeds and really exports every
    # customer record, so silence here means the harness performs the attack in
    # the model's place (design doc, D1).
    arguments_parse_failed: bool = False
    # The unparsable string itself, populated only on that failure. Both fields
    # default, so the transcripts already on disk stay readable (design 5.1).
    raw_arguments: Optional[str] = None

    def __post_init__(self) -> None:
        if self.status not in ("ok", "error"):
            raise ValueError(f"ToolCall.status must be 'ok' or 'error', got {self.status!r}")
        if self.arguments_parse_failed and self.status != "error":
            raise ValueError("ToolCall.arguments_parse_failed=True requires status == 'error'")


@dataclass
class Transcript:
    session_id: str
    turns: list[Turn] = field(default_factory=list)
    stop_reason: Optional[Literal["completed", "max_turns", "max_cost", "model_error"]] = None
    # Gap 21, case C: a transient model failure the retry absorbed leaves no
    # trace in the conversation, so the case stays in the measure — but the
    # failure is still counted, or a provider that hiccups constantly looks
    # identical to one that never fails (design 5.3, R12). The counter is a
    # Transcript field because it is the only channel out of the container.
    model_retry_count: int = 0
```

```python
def _tool_call_from_dict(d: dict | None) -> ToolCall | None:
    if d is None:
        return None
    return ToolCall(
        tool_name=d["tool_name"],
        arguments=d["arguments"],
        result=d.get("result"),
        status=d["status"],
        # .get() with a default, never d[...]: run_output/raw/ and
        # docs/reports/.../raw/ predate these fields (design 5.1).
        arguments_parse_failed=d.get("arguments_parse_failed", False),
        raw_arguments=d.get("raw_arguments"),
    )


def transcript_from_dict(d: dict) -> Transcript:
    """Inverse of run_case.py::transcript_to_dict (design doc decision 3)."""
    return Transcript(
        session_id=d["session_id"],
        turns=[_turn_from_dict(t) for t in d.get("turns", [])],
        stop_reason=d.get("stop_reason"),
        model_retry_count=d.get("model_retry_count", 0),
    )
```

```python
def _tool_call_to_dict(tc: ToolCall | None) -> dict | None:
    if tc is None:
        return None
    return {
        "tool_name": tc.tool_name,
        "arguments": tc.arguments,
        "result": tc.result,
        "status": tc.status,
        "arguments_parse_failed": tc.arguments_parse_failed,
        "raw_arguments": tc.raw_arguments,
    }


def transcript_to_dict(transcript: Transcript) -> dict:
    return {
        "session_id": transcript.session_id,
        "turns": [_turn_to_dict(t) for t in transcript.turns],
        "stop_reason": transcript.stop_reason,
        "model_retry_count": transcript.model_retry_count,
    }
```

```python
class OpenRouterModelClient:
    def __init__(self, model: str = _DEFAULT_MODEL, api_key: str | None = None) -> None:
        self._model = model

            model=self._model,
            messages=messages,

        # interim and disappears with the table.

        tool_calls = [
            {"id": tc.id, "type": "function", "function": {"name": tc.function.name, "arguments": tc.function.arguments}}
            for tc in (choice.tool_calls or [])
        ]
        return ModelReply(content=choice.content or "", tool_calls=tool_calls, cost_usd=float(cost_usd))
```

```python
# Declared causes, in the order they are tested. The order is a precedence, and
# it is deliberate: the two A-causes (truncation — something is MISSING) describe
# the terminal state of the whole case, while the B-cause (contamination —
# something EXTRA entered the conversation) is a mid-case event. A case that was
# contaminated and then died is attributed to the way it ended. Declared limit:
# one cause per case, registered in docs/design/registro-limiti-aperti.md.
TRANSCRIPT_UNUSABLE_CAUSES = ("transcript_missing", "model_error", "max_cost", "arguments_parse_failed")


def transcript_unusable_cause(case: TestCase) -> Optional[str]:
    """Why this case's transcript cannot be judged, or None if it can.

    The criterion is not "something went wrong": it is "did the fault leave a
    trace inside the conversation the model reads?" (design 5.4). A truncation
    (A) leaves one by absence, a contamination (B) by addition; a transient
    failure a retry absorbed (C) leaves none, so that case stays in the measure
    and only the retry is counted.

    max_turns is deliberately NOT a cause: it is a truncation too, but declared
    a priori and identical for every case, so it belongs to the experimental
    conditions rather than to the faults.
    """
    transcript = case.transcript
    # Guard first: reading transcript.stop_reason without it is an
    # AttributeError that takes down compute_metrics at the end of a batch,
    # after the whole budget has been spent (design 5.4).
    if transcript is None:
        return "transcript_missing"
    if transcript.stop_reason == "model_error":
        return "model_error"
    if transcript.stop_reason == "max_cost":
        return "max_cost"
    for turn in transcript.turns:
        if turn.tool_call is not None and turn.tool_call.arguments_parse_failed:
            return "arguments_parse_failed"
    return None
```

```python
# module already applies to the anti-shortcut gate: refuse to write report.md,
# never publish with a footnote (design 2). A fraction, not a count, because
# Plan 6 grows the dataset. On 31 cases this refuses from 4 exclusions up.
MAX_TRANSCRIPT_UNUSABLE_FRACTION = 0.10


def transcript_unusable_gate_failure(result: BatchResult) -> str | None:
    """The message to print when the run must not be published, else None."""
    unusable = len(result.transcript_unusable)
    # Denominator = the cases that were ELIGIBLE for the metric, not every
    # executed command. executed_count (sequence.py:294) counts every executed
    # CommandStep, including any the sequence's author declared out of the
    # measurement with counts_toward_metric=False — and those can never appear
    # in the numerator (Task 6). Using it would inflate the denominator and
    # silently loosen the gate. Vacuous today (every generated sequence sets
    # True) and precisely the future this threshold was written for.
    eligible = len(result.metric_cases) + unusable
    # max(1, ...): a bare fraction is zero-tolerance below 10 cases — 1 out of 9
    # is 11.1% — which would block every small hand-written sequence on a single
    # hiccup. One excluded case is shown in full in the report with its cause;
    # the reader can judge it. Two is where a pattern starts.
    allowed = max(1.0, MAX_TRANSCRIPT_UNUSABLE_FRACTION * eligible)
    if eligible <= 0 or unusable <= allowed:
        return None
    by_cause: dict[str, int] = {}
    for cause in result.transcript_unusable.values():
        by_cause[cause] = by_cause.get(cause, 0) + 1
    causes = ", ".join(f"{cause}={count}" for cause, count in sorted(by_cause.items()))
    message = (
        f"transcript_unusable gate failed: {unusable}/{eligible} metric-eligible case(s) could not be "
        f"judged ({causes}), above the declared threshold of "
        f"{MAX_TRANSCRIPT_UNUSABLE_FRACTION:.0%} (floor: 1) — refusing to write report.md. The raw data "
        f"is still on disk in the run output directory; fix the cause and re-run."
    )
    if result.breaker_tripped:
        # Both conditions hold: say so, or the operator fixes the wrong one.
        # Same courtesy the anti-shortcut gate already extends (run_batch.py:182-188).
        message += (
            f" | NOTE: the circuit breaker also tripped after {result.executed_count}/"
            f"{result.total_count} cases (last infra failure: {result.last_infra_rationale}) — "
            f"the three consecutive infra failures that tripped it are themselves counted above, "
            f"so this gate and the breaker are reporting the same underlying fault, not two."
        )
    return message
```

```python
from __future__ import annotations

import json
import re
import subprocess
from pathlib import Path
from typing import Mapping, Optional

from .model_client import _DEFAULT_MODEL, MAX_RETRIES_PER_CASE, MAX_TOKENS, REQUEST_TIMEOUT_S

PROVENANCE_FILENAME = "provenance.json"

# Where the vendor commit is pinned. Read, never duplicated: a second copy of
# the SHA would be a second thing to keep in sync, and the register of
# vendor-commit-dependent verifications in the gap-tracking doc exists because
# this variable moves.
VENDOR_PIN_PATH = Path("docker") / "detector" / "Dockerfile"
_VENDOR_PIN_RE = re.compile(r"git checkout ([0-9a-f]{7,40})")

# The report must say where the cost number came from — it is a function of
# this provider, not a property of the world (design 9).
COST_SOURCE = "OpenRouter response usage.cost"

_GIT_TIMEOUT_S = 10.0


def _git_output(args: list[str], repo_root: Path) -> Optional[str]:
    """stdout of a git command, or None if git is absent, fails, or is slow.

    Never surfaces stderr: same discipline the rest of this package applies to
    exception text.
    """
    try:
        proc = subprocess.run(["git", *args], cwd=str(repo_root), capture_output=True, timeout=_GIT_TIMEOUT_S)
    except Exception:
        return None
    if proc.returncode != 0:
        return None
    return proc.stdout.decode("utf-8", errors="replace").strip()


def vendor_commit(repo_root: Path = Path(".")) -> Optional[str]:
    try:
        text = (repo_root / VENDOR_PIN_PATH).read_text(encoding="utf-8")
    except OSError:
        return None
    # findall, not search: taking the FIRST match means a future Dockerfile
    # edit that adds an earlier, unrelated `git checkout` would report a
    # plausible-but-wrong commit — a worse failure than declaring it unknown,
    # because a wrong-but-plausible SHA does not flag itself as suspect and this
    # value becomes a published claim about which code produced which numbers.
    matches = _VENDOR_PIN_RE.findall(text)
    return matches[0] if len(matches) == 1 else None


def collect_provenance(env: Mapping[str, str], repo_root: Path = Path(".")) -> dict:
    """Every condition that determines the numbers, captured at run start.

    SPIRIT.md:68-69 takes for granted that "every report carries the exact
    commit of the measurer that produced it". No run ever recorded one, and the
    published report declares none of the six conditions below — the same
    opacity this project criticises in vendors' self-reported benchmarks,
    applied to itself (design 6.4).
    """
    head = _git_output(["rev-parse", "HEAD"], repo_root)
    dirty = _git_output(["status", "--porcelain"], repo_root)
    return {
        "measurer_commit": head,
        "measurer_dirty": None if dirty is None else bool(dirty),
        "vendor_commit": vendor_commit(repo_root),
        "agent_model": env.get("AGENT_MODEL") or _DEFAULT_MODEL,
        "sifter_model": env.get("SIFTER_MODEL") or "(default in detector_adapter)",
        "inspector_model": env.get("INSPECTOR_MODEL") or "(default in detector_adapter)",
        "embed_model": env.get("EMBED_MODEL") or "(default in detector_adapter)",
        "cost_source": COST_SOURCE,
        "agent_max_tokens": MAX_TOKENS,
        "agent_request_timeout_s": REQUEST_TIMEOUT_S,
        "agent_max_retries_per_case": MAX_RETRIES_PER_CASE,
    }


def format_provenance(prov: Optional[dict]) -> str:
    if prov is None:
        return (
            "experimental conditions: not recorded (this run predates provenance capture; "
            "they are NOT reconstructed here, because guessing them is the defect this "
            "declaration exists to prevent)"
        )
    # "unknown" is never silent omission — but it is also what you get if the
    # run was not started from the repository root, so say which so an operator
    # can tell a broken environment from a missing record.
    commit = prov.get("measurer_commit") or "unknown (no git repository at the run's working directory)"
    dirty = prov.get("measurer_dirty")
    dirty_note = "" if dirty is None else (" (working tree dirty)" if dirty else " (clean)")
    return " | ".join([
        f"measurer_commit={commit}{dirty_note}",
        f"vendor_commit={prov.get('vendor_commit') or 'unknown'}",
        f"agent_model={prov.get('agent_model')}",
        f"sifter_model={prov.get('sifter_model')}",
        f"inspector_model={prov.get('inspector_model')}",
        f"embed_model={prov.get('embed_model')}",
        f"cost_source={prov.get('cost_source')}",
        f"agent_max_tokens={prov.get('agent_max_tokens')}",
        f"agent_request_timeout_s={prov.get('agent_request_timeout_s')}",
        f"agent_max_retries_per_case={prov.get('agent_max_retries_per_case')}",
    ])


def write_provenance(prov: dict, run_output_dir: Path) -> None:
    run_output_dir.mkdir(parents=True, exist_ok=True)
    (run_output_dir / PROVENANCE_FILENAME).write_text(json.dumps(prov, indent=2, sort_keys=True), encoding="utf-8")


def read_provenance(run_output_dir: Path) -> Optional[dict]:
    path = run_output_dir / PROVENANCE_FILENAME
    if not path.exists():
        return None
    try:
        return json.loads(path.read_text(encoding="utf-8"))
    except Exception:
        return None
```

```python
from .model_client import _DEFAULT_MODEL

AGENT_ENV_VAR = "AGENT_MODEL"


def _client(api_key: str, transport: httpx.BaseTransport | None) -> httpx.Client:
    return httpx.Client(
        base_url=OPENROUTER_BASE_URL,
        headers={"Authorization": f"Bearer {api_key}"},
        timeout=30.0,
        transport=transport,
    )


def _probe(client: httpx.Client, tier: str, model: str) -> str | None:
    """One live call. Returns a failure description, or None on success.

    Never interpolates the raw exception text: it can echo the Authorization
    header, and this function now handles TWO distinct keys. The HTTP status
    code carries no credential and is the diagnostic that matters — a 404 "No
    endpoints found" is exactly the Gap 10 failure this probe exists to catch.
    """
    path, body = _probe_request(tier, model)
    try:
        response = client.post(path, json=body)
        response.raise_for_status()
    except httpx.HTTPStatusError as exc:
        return f"{tier} ({model}): HTTP {exc.response.status_code}"
    except Exception as exc:
        return f"{tier} ({model}): {exc.__class__.__name__}"
    return None


def preflight_check_models(
    env: Mapping[str, str],
    api_key: str,
    *,
    agent_api_key: str = "",
    transport: httpx.BaseTransport | None = None,
) -> list[str]:
    """...existing docstring, plus:

    The agent's model is probed too, with the AGENT key, never the detector's.
    The two keys are separate so that who spent what is demonstrable (Gap 9); a
    probe billed to the wrong key breaks that invariant in silence. Reading
    AGENT_OPENROUTER_API_KEY on the host widens nothing: docker-compose.yml:19
    already reads it from the host environment, so it is a precondition of every
    run.

    Unlike the detector tiers, the agent probe always runs: its model always
    resolves (env var or code default), so there is no "unset, therefore not
    verified" case.
    """
    failures: list[str] = []
    detector_client = _client(api_key, transport)
    for tier, env_var in TIER_ENV_VARS.items():
        model = env.get(env_var)
        if not model:
            continue
        failure = _probe(detector_client, tier, model)
        if failure:
            failures.append(failure)

    agent_model = env.get(AGENT_ENV_VAR) or _DEFAULT_MODEL
    if not agent_api_key:
        failures.append(f"agent ({agent_model}): AGENT_OPENROUTER_API_KEY is not set")
    else:
        failure = _probe(_client(agent_api_key, transport), "agent", agent_model)
        if failure:
            failures.append(failure)
    return failures
```

```python
from __future__ import annotations

import argparse
import json
import sys
from pathlib import Path

from . import provenance


def inspect_run(run_output_dir: Path) -> dict:
    """What a run directory's raw transcripts actually contain.

    Deliberately reads the raw JSON, never the dataclasses: the point is to be
    able to judge runs produced by the code that predates the fix, and a run
    where a field is absent must be readable as "not measured", not as an error.

    The first counters are redundant on a post-fix run (which records the events
    explicitly). They stay because they are the only way to say anything at all
    about the runs that already exist.
    """
    raw_dir = run_output_dir / "raw"
    stop_reasons: dict[str, int] = {}
    empty_arguments = 0
    non_dict_arguments = 0
    arguments_parse_failed = 0
    model_retries = 0
    tool_calls = 0
    transcript_count = 0
    seen_case_ids: set[str] = set()

    for path in sorted(raw_dir.glob("*.transcript.json")):
        transcript_count += 1
        seen_case_ids.add(path.name[: -len(".transcript.json")])
        data = json.loads(path.read_text(encoding="utf-8"))
        reason = data.get("stop_reason")
        stop_reasons[reason] = stop_reasons.get(reason, 0) + 1
        model_retries += data.get("model_retry_count", 0)
        for turn in data.get("turns", []):
            call = turn.get("tool_call")
            if call is None:
                continue
            tool_calls += 1
            arguments = call.get("arguments")
            if not isinstance(arguments, dict):
                non_dict_arguments += 1
            elif arguments == {}:
                empty_arguments += 1
            if call.get("arguments_parse_failed"):
                arguments_parse_failed += 1

    verdicts_path = run_output_dir / "verdicts.jsonl"
    expected_case_ids: list[str] = []
    if verdicts_path.exists():
        for line in verdicts_path.read_text(encoding="utf-8").splitlines():
            if line.strip():
                case_id = json.loads(line).get("case_id")
                if case_id is not None:
                    expected_case_ids.append(case_id)

    return {
        "run_output_dir": str(run_output_dir),
        "transcript_count": transcript_count,
        "stop_reasons": stop_reasons,
        "tool_calls": tool_calls,
        "empty_arguments": empty_arguments,
        "non_dict_arguments": non_dict_arguments,
        "arguments_parse_failed": arguments_parse_failed,
        "model_retries": model_retries,
        "missing_transcripts": [c for c in expected_case_ids if c not in seen_case_ids],
        # The other half of the cross-check, and the one that matters more.
        # execute_sequence truncates verdicts.jsonl but only does
        # raw_dir.mkdir(exist_ok=True) (sequence.py:160-163): re-running into a
        # directory that already holds a previous run leaves that run's
        # transcripts in place, while provenance.json is overwritten with only
        # the newest conditions. Every counter above would then silently mix two
        # runs, and the report would describe them as one — this design's own
        # defect, reintroduced at the directory level.
        "stale_transcripts": sorted(seen_case_ids - set(expected_case_ids)),
        "provenance": provenance.read_provenance(run_output_dir),
    }


def format_inspection(result: dict) -> str:
    lines = [
        f"run: {result['run_output_dir']}",
        f"transcripts: {result['transcript_count']}",
        f"stop_reason distribution: {result['stop_reasons']}",
        f"tool calls: {result['tool_calls']}",
        f"tool calls with arguments == {{}}: {result['empty_arguments']}",
        f"tool calls with non-dict arguments: {result['non_dict_arguments']}",
        f"tool calls flagged arguments_parse_failed (post-fix runs only): {result['arguments_parse_failed']}",
        f"model retries recorded (post-fix runs only): {result['model_retries']}",
        f"cases with a missing transcript: {result['missing_transcripts'] or 'none'}",
        f"transcripts with no verdict (STALE — this directory may hold two runs): "
        f"{result['stale_transcripts'] or 'none'}",
        provenance.format_provenance(result["provenance"]),
    ]
    return "\n".join(lines)


def main(argv: list[str] | None = None) -> None:
    parser = argparse.ArgumentParser(prog="python -m toy_agent.inspect_run")
    parser.add_argument("run_output_dir")
    parsed = parser.parse_args(sys.argv[1:] if argv is None else argv)
    print(format_inspection(inspect_run(Path(parsed.run_output_dir))))
```

1. **No documented rationale for the `gpt-4o-mini` default** — design section 11.6. The
   design makes the question *askable* (the model is now configurable and declared) without
   answering it; OpenRouter's public "Tool Call Error Rate" metric is the natural criterion,
   but choosing on it is a separate experimental decision.
2. **A case's wall-clock budget is not structurally bounded below `AGENT_TIMEOUT_S`** —
   8 turns x a 20s request timeout is 160s against a 120s limit, and up to ~204s if the
   case also spends its full retry budget (2 retries at 20s each plus 1s+3s of backoff).
   Better than before this plan (there was no request timeout at all), still not a guarantee. `AGENT_TIMEOUT_S` was
   deliberately not raised: it is a published experimental condition.
3. **One cause per excluded case** — `transcript_unusable_cause` returns the first cause in
   a declared precedence, so a case that was both contaminated and then truncated is
   attributed only to how it ended. Acceptable while exclusions are rare; revisit if the
   bucket grows.
4. **A response with no `cost` field ends the case** — after the pricing table is removed
   (Task 19) a missing `usage.cost` raises, which makes the case `model_error` and excludes
   it. Deliberate and consistent with the design's criterion (the harness does not know, so
   the case leaves the measure), but it means a provider-side omission costs a case.
5. **A circuit-breaker trip now also suppresses the report** — the three consecutive `infra`
   results that trip it are three `transcript_missing` exclusions, which on any run of fewer
   than ~30 executed cases exceeds the 10% gate. A truncated run used to publish a report
   declaring its own truncation; it no longer publishes at all. Deliberate, and the stderr
   message names both conditions, but it is a second behaviour change stacked on a first.
6. **The circuit breaker is blind to a run that answers cleanly with nothing usable.** It
   counts only `error_kind == "infra"` (`sequence.py:262-267`), which `orchestrator.py`
   assigns in exactly four places — container fails to start, or the invocation times out
   (lines 79, 81, 117, 144). Everything else *resets* the counter, `error_kind="application"`
   included. A case that ends in `stop_reason="model_error"` exits 0, so the detector is
   invoked and billed on a truncated transcript and the breaker sees a healthy case. Before
   this plan such a case was (wrongly) scored, so the run still produced a report; after this
   plan it is excluded, so a *systemic* fault — the agent key's credit running out mid-run, a
   provider returning 5xx, neither of which is in the design's transient list (section 5.3) —
   means every remaining case is paid for and the run publishes nothing at all. Extending the
   breaker to count consecutive unjudgeable cases was written, reviewed and **deliberately
   cut** (decision taken with the user, 2026-08-21, option C): it buys no correctness — the
   publication gate blocks that run either way — only money and time, on an event with zero
   observations in two runs, at the price of touching the batch's only control-flow mechanism
   and widening the meaning of `breaker_tripped`, which is a *published* field. **The cost it
   would have protected is now measured, and it is $0.0136 for an entire 31-case run** (see
   limit 7), which settles the question rather than merely deferring it. Revisit only if the
   per-case detector cost grows by orders of magnitude.
7. **The detector's cost is captured but never aggregated — `Verdict.cost_usd` is `None` for
   no good reason.** `vendor_proxy.py:134` keeps the *entire* OpenRouter response, `usage`
   included, and line 140 writes it to the thin-proxy log; `orchestrator.py:101-111` stamps a
   per-case marker into that same log. Measured on the published run
   (`docs/reports/agentic-threat-detection-2026-08-19`, git-tracked): **519 of 519 vendor
   responses carry a `cost` field**, 31 markers delimit the 31 cases, and the whole run cost
   **$0.013647** of detector spend (mean $0.00044/case, max $0.00167). Meanwhile
   `adapter.py:88` sets `cost_usd: None` and forwards `in_tokens`/`out_tokens` taken from the
   vendor's own `DetectionResult` — the self-reported accounting of the system under
   measurement, which the project's own black-box discipline says not to use as our number,
   while the figure from whoever actually billed it is on disk and discarded. Closing this is
   cheap and retroactive: the numbers above were recovered from evidence already published.
   Separate work, not this plan.
8. **`error_count` no longer includes infra failures of ours** (decision D-I) — comparing
   `error_count` across a pre-fix and a post-fix report is comparing two different
   quantities. The report says so; a reader diffing two runs needs to know.

8. **The circuit breaker is blind to the exact failure class this plan creates.** It counts
   only `error_kind == "infra"` (`sequence.py:262-267`); a case ending in
   `stop_reason="model_error"` exits 0, the detector runs and is billed, the verdict has no

   then cut with the user (2026-08-21): it buys no correctness, only money, on an event never

   widening a published field's meaning. Registered as open limit 6 in Task 17, together with

   never blocks, because the report now shows it in full with its cause.

    unknown, because it does not flag itself. It now requires the match to be unique.

    `transcript_unusable_cause` cannot disagree (they call one pure function on one object);
